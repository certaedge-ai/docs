# 创建 API Key（令牌）

API Key 用于验证模型调用。建议为每个工具创建独立密钥，便于查看用量和单独停用。

## 1. 创建密钥

1. 登录后打开<PlatformLink to="keys">API 密钥</PlatformLink>页面，点击“创建 API 密钥”。
2. 在“名称”填写用途，例如 `cursor-work`；首次创建时“数量”保留 `1`。
3. 在“分组”选择账号实际可用的选项。若默认选中 Auto 且你不需要自定义顺序，可保留全局继承设置。
4. 设置有效期。临时测试可选择较短有效期；选择“永不过期”时仍需定期管理密钥。
5. 在“额度设置”中，若要限制测试预算，先关闭“无限配额”，再填写大于 `0` 的额度。
6. 点击“创建”。看到新密钥出现在列表中，才表示创建完成。

*图为字段示意，实际界面以控制台为准。*

## 2. 按需设置访问范围

展开创建表单中的“高级设置”，可设置模型限制和 IP 白名单。

| 项目 | 如何设置 |
| --- | --- |
| 模型限制 | 选中要允许的模型；留空表示不额外限制模型，但仍受账号和分组权限约束 |
| IP 白名单 | 仅在知道实际请求出口 IP 时填写；不确定时先留空，避免把自己拦在外面 |
| Auto 分组 | 初次使用保留全局继承；需要自定义时至少选择一个可用分组 |
| 有限额度 | 额度耗尽后需要提高密钥额度；这不会给账号充值 |

“无限配额”只表示不设置这把密钥的独立额度上限，不代表调用免费或账号余额无限。

## 3. 复制完整密钥

在列表中找到刚创建的密钥，使用密钥旁的复制按钮，或行菜单中的“复制密钥”。复制得到的完整密钥通常以 `sk-` 开头，直接粘贴到客户端 API Key 字段。

不要手动复制列表中的打码文本，也不要在已带 `sk-` 的密钥前再次添加 `sk-`。

## 4. 验证是否可用

按[首次调用](/getting-started/first-request)发送一条简短消息，再打开<PlatformLink to="logs">使用日志</PlatformLink>核对请求。

401 时检查密钥是否完整、过期或停用；模型不可用时检查模型 ID、分组与模型限制。泄露时先停用旧密钥，再创建并更新客户端配置。
