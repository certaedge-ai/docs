# Music and Lyrics {#音乐与歌词}

This page covers the platform's enabled **SunoAPI-compatible endpoints**. Lyrics and music are separate actions, and your account needs access to the corresponding models. Use your CertaEdge API Key; you do not need to give the client a key from another platform.

Set up authentication as described in the [overview](/en/generation/). These endpoints use `/suno/...` paths. Do not append `/suno` after `/v1`.

## Lyrics: start with a minimal task {#歌词-先跑通最小任务}

Create `lyrics.json`:

```json
{
  "prompt": "Write Chinese lyrics about walking through a city after the rain, including a verse and chorus."
}
```

Submit:

```bash
curl -sS -X POST https://certaedge.com/suno/submit/lyrics \
  -H "Authorization: Bearer $CERTAEDGE_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @lyrics.json
```

A successful native submission has this structure:

```json
{
  "code": "success",
  "message": "",
  "data": "task_EXAMPLE"
}
```

Check `code` and save the actual `data` value. Here, `data` is the task ID, not the lyrics.

## Music: provide a description and version {#音乐-填写描述与版本}

With music access enabled, create `music.json`:

```json
{
  "gpt_description_prompt": "Gentle piano and strings for a city scene after the rain, with no vocals.",
  "make_instrumental": true,
  "mv": "YOUR_ENABLED_MUSIC_VERSION"
}
```

`mv` is an enabled music version value, **not** the `suno_music` name from the catalog. Use the version specified in the model's instructions. Do not send `YOUR_ENABLED_MUSIC_VERSION` literally; if no version is provided, confirm it with the platform first. `make_instrumental: true` requests instrumental music, subject to the selected version's capabilities.

```bash
curl -sS -X POST https://certaedge.com/suno/submit/music \
  -H "Authorization: Bearer $CERTAEDGE_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @music.json
```

The native submission path determines whether the action generates lyrics or music. You do not need to guess an additional `model` parameter to switch actions.

## Query and read the results {#查询并读取结果}

Set the task ID in your current terminal:

```bash
export CERTAEDGE_TASK_ID='task_EXAMPLE'
curl -sS "https://certaedge.com/suno/fetch/$CERTAEDGE_TASK_ID" \
  -H "Authorization: Bearer $CERTAEDGE_API_KEY"
```

The outer `code: success` means the query succeeded. Also check `data.status`: only `SUCCESS` means generation succeeded; `FAILURE` means it failed. For other in-progress states, wait as described in the [polling guide](/en/generation/lifecycle).

On success, inspect the task data. For lyrics, read the text it contains. Music may return multiple items and cover images; do not read only the first array item. To download audio or cover images, use the [generic task artifacts API](/en/generation/tasks#列出和下载产物) to list the actual artifacts and select the required items.

## Flexible workflows {#灵活用法}

- Use a [Dify workflow](/en/tools/dify#用工作流调用生成任务) to prepare a music description before submitting the task.
- Use [n8n](/en/tools/n8n#生成任务工作流) to wait for the results and save audio and cover images.
- When using [background Responses](/en/generation/responses) as a common interface, keep its `resp_...` identifier. Do not mix it up with the native API's `data` field.
